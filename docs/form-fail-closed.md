# Fail-closed формы

Формы оценки по фото и обратного звонка не должны создавать ложное ощущение отправки, если JavaScript отключён или загрузился не полностью.

## Какие отказы закрыты

### Полностью отключённый JavaScript

В публичной сборке кнопка отправки изначально отключена. Рядом отображается статическое сообщение: данные не отправлены, для связи нужно позвонить Ивану.

Контакт, задача и другие поля не имеют `name`, поэтому браузер не передаёт их как обычную HTML-форму и не добавляет контакт в URL.

### Частично загрузившийся JavaScript

Первым подключается небольшой модуль `js/form-fail-closed.js`. Он:

- предотвращает нативную отправку и перезагрузку страницы;
- после установки защиты включает кнопку;
- не мешает основному обработчику сохранить заявку через существующий lead endpoint;
- проверяет, изменился ли статус после попытки отправки;
- если основной обработчик не запустился, сообщает, что данные не отправлены;
- оставляет введённые значения в полях;
- показывает прямую кнопку звонка и безопасный следующий шаг;
- снимает зависшее `aria-busy` и возвращает кнопку в рабочее состояние.

## Privacy-граница

Модуль защиты формы:

- не сохраняет значения полей;
- не вызывает `fetch`;
- не читает имя, телефон, адрес или описание задачи;
- не пишет в `localStorage` или `sessionStorage`;
- не использует буфер обмена;
- не отправляет аналитику;
- не передаёт контакт в URL.

Основной обработчик, Supabase payload, уведомления и существующие fallback-сценарии не меняются.

## Сборка

`tools/form_fail_closed.py` перед fingerprinting JavaScript:

1. находит все публичные формы `id="request-form"`;
2. добавляет состояние `data-form-safety="pending"`;
3. отключает submit-кнопку;
4. добавляет `<noscript>` с телефоном;
5. запрещает появление `name` у контактного поля;
6. подключает form safety script перед `main.js`;
7. проверяет идемпотентность преобразования.

После выполнения скрипта форма получает `data-form-safety="active"`, а кнопка становится доступной.

## Live-контроль

Ежедневная и post-deploy проверка читает `/zayavka/` и `/kontakty/` на реальном домене. Она требует увидеть состояние `pending`, отключённую кнопку, no-JS сообщение, телефон и cache-busted модуль `form-fail-closed`.

Проверка не нажимает кнопку, не вызывает lead endpoint и не создаёт production-заявки. Если опубликована старая или неполная форма, общий live workflow завершается ошибкой и сохраняет диагностический отчёт.

## Проверка

- `tests/e2e/no-js-accessibility.spec.mjs` — полностью отключённый JavaScript, отключённая кнопка, сохранение полей при Enter и телефонный fallback.
- `tests/e2e/form-fail-closed.spec.mjs` — основной `main.js` не загрузился, но форма не перезагрузилась, значения остались, появился честный статус и звонок.
- `tools/check_form_fail_closed.py` — структура build-time защиты, порядок скриптов, отсутствие транспорта и локального хранения.
- `tools/form_fail_closed.py` — отдельный self-test преобразования.
- `tools/check_live_conversion.py` — live-маркеры обеих форм без отправки данных.

Локальная проверка:

```bash
python tools/form_fail_closed.py
python tools/check_form_fail_closed.py
python tools/check_live_conversion.py --self-test
python tools/build_pages.py
npm run test:e2e -- tests/e2e/form-fail-closed.spec.mjs tests/e2e/no-js-accessibility.spec.mjs
python tools/run_quality_checks.py
```
